# Connect-phase decisions

1. **Review stack**: `npm run review` runs `docker-compose.yml` under the compose project `somar-review`, probing free ports (app 8080 → 8787…, gateway 8000…, db 54322 → 55432…) and storing them in the gitignored `.review.json`, so re-runs reuse the same ports and data. `--rebuild` rebuilds the app image after code changes; `review:stop -- --wipe` deletes the volumes.
2. **Review credentials** are the public Supabase demo JWT keys and fixed demo passwords (`Admin@12345`, `Demo@12345`); they exist only in the local review stack.
3. **Tour isolation**: `npm run tour` creates a temporary "tour" university (cooldown 0) for the first-login and scan screenshots and deletes it afterwards, so the demo data never changes; admin screens show the demo university.
4. **Tour browser**: the installed Microsoft Edge with Chromium's fake camera flags; the camera screenshot therefore shows the browser's synthetic test pattern.
5. **UI fixes found by the tour**: the full-screen camera and the scan result popup now sit above the bottom tab bar (z-index 60/70), and the college name in the scan popup is no longer rendered in the monospace font.
6. **Production env file**: `.env.production` (gitignored) holds the Postgres credentials as parts (`POSTGRES_USER/PASSWORD/HOST/PORT/DB`); tooling builds `DATABASE_URL` with URL-encoding so special characters in the password never break it. `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` and `VITE_VAPID_PUBLIC_KEY` are derived from their server counterparts when left empty.
7. **Same-instance check**: self-hosted keys carry no project ref, so "same instance" is proven by the gateway accepting both keys (each is verified against the instance's `JWT_SECRET`) plus an identical `iss`.
8. **Public Postgres port**: the owner exposed Postgres on 5432 so migrations and `doctor` can run from his machine; recommended hardening after go-live is a firewall rule limiting 5432 to trusted IPs (or disabling the public port and running tooling from the server).
9. **Coolify Supabase env names**: the template maps short names (`DISABLE_SIGNUP`, `ENABLE_EMAIL_AUTOCONFIRM`, `ENABLE_EMAIL_SIGNUP`, `ENABLE_PHONE_SIGNUP`, `ADDITIONAL_REDIRECT_URLS`, `JWT_EXPIRY`) onto `GOTRUE_*`; the owner was given both forms. Verified live: signup disabled, email enabled, autoconfirm on, phone off.
10. **Student email domain** stays `somar.local`: GoTrue accepted it (admin create with `email_confirm` → password sign-in → delete). Auto-confirm is a safety net; the provisioning code already confirms at creation.
11. **Migration runner for self-hosted**: `npm run db:apply` replaces `supabase db push`; it records filename + SHA-256 (CRLF-normalized) in `public._schema_migrations` (RLS on, no grants to anon/authenticated), runs each file in its own transaction, refuses to re-apply a changed file unless `--force <file>`, and supports `--dry-run`. `db:status` and `db:verify` complement it. The migrations are idempotent, so the first tracked run on a database that already had them applied is safe.
12. **Storage setup**: `npm run storage:setup` creates/updates both buckets through the Storage API (SQL fallback) as private with `file_size_limit` = `MAX_PHOTO_MB` (default 5 MB) and mimes `image/jpeg,image/png,image/webp`, re-applies the two read policies from `0004_storage.sql`, and proves a 1 KB upload → 60 s signed URL → fetch → delete round trip; the signed URL host on production is the public `somar-supa.ahmad-zaven.io`.
13. **Brand assets**: `assets/somar_logo.png` (1080×1080 transparent) is the master; `scripts/generate-icons.ts` trims its transparent margin (visible 840×665) and writes `icons/logo.png` (360 px wide, palette PNG, ~35 KB, used on the login screen, header and printed card), 192/512 icons on white with 8 % padding, maskable 192/512 with 20 % padding (inside the safe zone), a 180 px apple-touch icon, a 48 px `favicon.png`, and a monochrome white `badge-72.png` for Android notifications. The placeholder SVG hawk was removed.
14. **Local ports**: the review stack owns 8787, so the local dev/E2E server moved to 8788 (`.env`, not committed).
15. **Doctor never touches time**: the scan smoke test (#11) proves outbound → return → third rejected → off-day → no-balance → cooldown using per-university settings (cooldown 0, then 5), a work-day set that excludes today and a −3 single-week adjustment, inside `__DOCTOR__<ts>`; it never writes `private.test_clock`, so the live system's clock is never frozen. Cleanup (auth users + university cascade + audit rows) is itself a checked item.
16. **Upload probe**: `POST /api/_probe/upload` streams and discards the body (cap 64 MB) and requires the service-role key as a Bearer token (constant-time compare), so it cannot be used as an open upload sink. Default probe size `MAX_UPLOAD_MB=10` (import files and photos are far smaller).
17. **Clock drift** is measured at the moment of each response (DB `now()` and the app's `Date` header) against the machine running doctor; threshold 60 s.
18. **VAPID**: `npm run generate:vapid -- --write .env.production` writes the pair (private key never printed) and refuses to overwrite existing keys, because rotation invalidates every stored push subscription. Generated once for production.
19. **Node 22**: the Dockerfile moved to `node:22-slim` and the Node 20 WebSocket shim (`ws` transport) was removed from the API and tooling; `npm run verify` (64 unit + 28 integration) and `docker build` pass, the container is healthy with `db: up` and logs no supabase-js deprecation notice. Unpacked image ≈ 305 MB. Root `engines.node` is now `>=22`.
20. **`DATABASE_URL` is not given to the app container**: the running app only talks to Supabase over HTTPS; the database URL is used by the owner's tooling (`db:apply`, `doctor`, `onboard`, `import:students`) from `.env.production`. Keeping it out of Coolify reduces where the Postgres password lives.
21. **Build-time `NODE_ENV`**: Coolify injected `NODE_ENV=production` into the build (the variable was marked "Available at Buildtime"), which made `npm ci` omit devDependencies and the build failed with `tsc: not found`. The build stage now runs `npm ci --include=dev`, so platform-injected `NODE_ENV` can no longer break the build; the owner also marks `NODE_ENV` runtime-only.
22. **Env-file quoting**: values containing `#` must be double-quoted in `.env.production` (dotenv and `node --env-file` treat an unquoted `#` as a comment). The bootstrap failure was diagnosed by comparing raw vs parsed length without printing the value.
23. **Demo-seed guard** (runs before any write): `seed:demo` aborts (exit 2, Arabic message) when `NODE_ENV=production`, when `SUPABASE_URL` is not a local host (localhost / 127.0.0.1 / host.docker.internal / kong) — this protects the still-empty production database — or when any university other than the demo one exists; `--force-demo` overrides. The demo university is identified by name **and** prefix, so a real university that also uses `SHB` is never treated as demo data (and `--reset` can never delete it). Verified against production: exit 2, zero rows written.
24. **Onboarding**: `npm run onboard` upserts the university by prefix, inserts the 3 colleges and the 39 approved areas (`supabase/seed/areas-shahba.txt`) with `on conflict do nothing`, and matches packages by name (update, else insert) — all in one transaction with an audit entry; the logo is trimmed, fitted to 512×512 PNG and uploaded to `university-logos/{id}/logo.png` after the commit. `--dry-run` rolls back. Nothing is ever deleted.
25. **No-dash transport numbers** (owner's choice: `SHB0001`): new migration `0005_transport_separator.sql` adds `universities.transport_separator` (`'-'` default, or `''`), updates `allocate_transport_number`, and makes `release_transport_number` read the trailing digits. Existing universities keep the dash; the admin UI has a «شكل رقم النقل» selector (new universities default to no dash). Covered by a new integration test.
26. **7-character first passwords**: `SHB0001` is 7 characters; production GoTrue accepted a 7-character password (tested with a throwaway account), and the app then forces an 8+ character password on first login.
27. **Currency label**: package prices are shown with «دولار» (owner quoted USD); the system still stores no payments.
28. **University logo not set**: only the Somar logo was supplied; using it as the university logo would print it twice on every card, so the university logo stays empty until the owner uploads the Al-Shahba logo from «الجامعات».
29. **Package set** is the owner's choice (2, 3 and 5 trips); he was told that ~30 % of students work exactly 4 days and would need the 5-trip package.
30. **Stop library** (owner's request): migration `0006_stop_library.sql` adds `public.stops` (per university, unique name, RLS: read by the university, write by staff) and `route_stops.stop_id` (`on delete restrict`, unique per route). Name, Maps link, coordinates and area now live on the library stop; `route_stops` keeps only order and time (legacy columns kept nullable and back-filled into the library). Editing a library stop updates every route using it; a stop in use can be deactivated but not deleted. The schedule-change notification takes the stop name from the library. New admin screen «نقاط الوقوف»; the route editor picks a stop from a dropdown (stops already on the route are hidden). Covered by a new integration test and E2E test 8.
31. **Command-line import**: `npm run import:students -- --file … --university SHB --dry-run|--commit [--env …]` reuses the exact engine of the admin wizard. The dry run writes `import-preview.xlsx` (summary / all rows / rejected, Arabic reasons); the commit writes `import-result.xlsx` with every account (transport number = first password, name, student number, phone, college). Audit entries are attributed to the admin from `BOOTSTRAP_ADMIN_CODE`. Both output files and any `assets/*.xlsx|xls|csv` are gitignored because they hold personal data and first passwords.
32. **Import timing**: the real `--commit` waits until routes and stop times are final, because every later time correction notifies all active students; the dry run can run anytime (writes nothing).
33. **Route tools** (owner's request): migration `0007_duplicate_route.sql` adds `duplicate_route(route_id, name)` (staff of that university only, audited) that copies a route with all its stops, order and times in one transaction; the UI names the copy «… (نسخة)» and opens it for editing. Each stop inside a route has «نسخ إلى خط آخر», which lists the other routes (routes already containing that stop are disabled) and appends the stop with the same time. The stop picker is now search-as-you-type with Arabic spelling folding (أ/ا، ة/ه، ى/ي). Covered by a new integration test and an extended E2E test 8.
34. **University creation locked** (owner's request): the «إضافة جامعة» button shows a lock and opens a message («رقّي باقتك مع أحمد سباغ لتفتحلك») instead of the form. This is a UI-level lock only; editing existing universities is unchanged, and the database still allows the admin to insert universities (onboarding tooling keeps working).
35. **Vendor credit**: «This System is made by Trinode» is shown at the bottom of every screen (login, student, supervisor and admin layouts), in English on the owner's request and excluded only for that exact sentence in the no-English E2E check; it is hidden when printing so it never appears on the transport cards.
36. **Transport-number release fix**: `release_transport_number` (migration `0008`) now reads the sequence after the university's own prefix + separator instead of taking the trailing digits, which was wrong for a prefix ending in a digit with no separator (`TA1` + `0002` → `30002`). `SHB` was never affected. The integration test now always uses a digit-ending prefix.
37. **Integration tests run in a single process** (`pool: forks`, `singleFork`): all files share the database's frozen test clock, and Vitest's per-project `fileParallelism: false` alone did not stop files from overlapping, which made the cooldown test fail intermittently. Verified 8/8 green runs after the change.
38. **First-login setup** (owner's request): migration `0009_student_setup.sql` adds `students.setup_completed_at` and `public.student_schedule` (one row per chosen day: outbound and return time, return must be later). After the password and photo steps, a student without a completed setup is sent to `/setup`: a searchable area picker, a free-text residence description, and a weekly table (days in the university's week order) with outbound/return times for each attended day. `save_my_setup` validates everything in the database and replaces the schedule atomically. The chosen days also become the student's official `work_days`, so the package/eligibility rules follow what the student declared. Students can edit it later from «حسابي» → «جدول دوامي» (`/schedule`); staff see it on the student detail page.
39. **Schedule statistics**: new admin screen «إحصائيات الدوام» (`/admin/stats`), backed by `schedule_stats` (staff of that university only) and `setup_progress`. It shows how many students completed setup, then per-day tabs with areas × time-slot tables for outbound and return, with totals.
40. **Collapsible route cards** (owner's request): in both the admin and student route lists, each route is a card that opens and closes on click; the header shows the name, direction, time and stop count.
41. **Demo data backfill**: the demo seed fills schedules for demo students that already have a photo, so the review stack and the tests are not stuck at `/setup`. It still refuses to run against production.
42. **Mandatory notifications** (owner's request): every signed-in user (student, supervisor, university supervisor, admin) is held on a full-screen «فعّل الإشعارات للمتابعة» gate until this device has a push subscription; it comes after the password, photo and setup steps and only offers the enable button and sign-out. If the browser permission was blocked, the gate explains how to re-allow it from the site settings and re-checks. On an iPhone outside the installed app (Safari has no web push there) the gate asks to install the app first. A browser that cannot do web push at all (very old or in-app browsers) is let through, because nothing the user does could satisfy the gate; the same applies if the VAPID public key is missing from the deployment, so a misconfiguration never locks everyone out. Each time the gate passes, the device's subscription is re-linked to whoever is signed in (shared phones).
43. **One-tap install button** «تنزيل التطبيق»: shown on the login screen, the notifications gate and in the top bar of the student, scanner and admin screens, whenever the app can be installed and is not already running installed. On Android/desktop Chromium one tap opens the browser's own install dialog (the `beforeinstallprompt` event is captured at startup so the button is ready immediately). iPhone has no programmatic install, so there the button opens the three Safari steps. It replaces the old dismissible install banner.
